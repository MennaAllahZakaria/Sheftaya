# Sheftaya - Backend API

## Project Overview
Sheftaya is a robust job and shift management system designed to connect employers with workers. This project provides a powerful Backend API that facilitates job application processes, comprehensive shift management, a real-time notification system, and detailed tracking of worker statuses across various shifts. The system is built using Node.js and Express.js, leveraging MongoDB as its primary data store, and integrates Socket.io for efficient real-time communication.

## Key Features
-   **User Management**: Secure user authentication (login, registration), and role-based access control for workers and employers.
-   **Job Management**: Functionality for creating, updating, deleting, and searching for job postings.
-   **Job Applications**: A streamlined system for workers to apply for jobs and for employers to accept or reject applications.
-   **Shift Management**: Advanced tracking of worker status throughout a shift, including 'on the way', 'arrived', 'arrival approved', 'shift started', and 'shift ended'.
-   **Real-time Notifications**: Instant updates and alerts delivered via Socket.io and Firebase Cloud Messaging (FCM).
-   **Reporting and Support System**: Tools for users to report issues and access support.
-   **Penalty System**: Mechanism to manage and apply penalties based on predefined rules.

## Technologies Used
-   **Node.js**: JavaScript runtime environment for server-side logic.
-   **Express.js**: A fast, unopinionated, minimalist web framework for Node.js, used for building the API.
-   **MongoDB**: A NoSQL document database, providing flexibility and scalability for data storage.
-   **Mongoose**: An elegant MongoDB object modeling tool for Node.js, simplifying data interaction.
-   **Socket.io**: A library that enables real-time, bidirectional, event-based communication between the server and clients.
-   **Firebase Admin SDK**: Utilized for sending push notifications via Firebase Cloud Messaging (FCM).
-   **JWT (JSON Web Tokens)**: For secure, stateless authentication across the API.
-   **Bcrypt**: A library used to hash passwords securely.
-   **Cloudinary**: A cloud-based image and video management service for handling media uploads.
-   **Nodemailer**: A module for Node.js applications to allow easy email sending.
-   **Node-cron**: A tool for scheduling tasks to run at specific intervals.

## Setup and Installation

### Prerequisites
-   **Node.js**: Version 18 or newer.
-   **MongoDB**: An instance of MongoDB, either locally installed or a cloud service like MongoDB Atlas.
-   **Cloudinary Account**: Required for image storage and management.
-   **Firebase Project**: With Firebase Cloud Messaging (FCM) configured for push notifications.

### Install Dependencies
Navigate to the project root directory and run:
```bash
npm install
```

### Environment Variables
Create a `.env` file in the root of your project and populate it with the following variables. Replace placeholder values with your actual credentials and configurations.

```dotenv
PORT=5000
NODE_ENV=development
DB_URI=mongodb://localhost:27017/sheftaya
JWT_SECRET_KEY=your_jwt_secret_key
JWT_EXPIRE_TIME=30d
JWT_COOKIE_EXPIRE=30

CLOUDINARY_CLOUD_NAME=your_cloudinary_cloud_name
CLOUDINARY_API_KEY=your_cloudinary_api_key
CLOUDINARY_API_SECRET=your_cloudinary_api_secret

EMAIL_USER=your_email@example.com
EMAIL_PASS=your_email_password

FIREBASE_PROJECT_ID=your_firebase_project_id
FIREBASE_PRIVATE_KEY_ID=your_firebase_private_key_id
FIREBASE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n" # Ensure this is correctly escaped if used directly in .env
FIREBASE_CLIENT_EMAIL=your_firebase_client_email

AI_API_KEY=your_ai_api_key
```

### Running the Project

To run the project in **development mode** (with `nodemon` for auto-restarts):
```bash
npm run dev
```

To run the project in **production mode**:
```bash
npm run start:prod
```

## API Endpoints

The following table outlines the main API routes available in the Sheftaya backend:

| Endpoint            | Description                                         |
| :------------------ | :-------------------------------------------------- |
| `/auth`             | Handles user authentication, registration, and profile management. |
| `/admin`            | Provides administrative functionalities for managing users and jobs. |
| `/jobs`             | Manages job postings, including creation, retrieval, updates, and deletion. |
| `/applications`     | Facilitates job applications, worker acceptance/rejection, and application status tracking. |
| `/shifts`           | Dedicated to managing the real-time status and flow of worker shifts. |
| `/notifications`    | Manages user notifications, allowing retrieval and marking as read. |
| `/support`          | Provides endpoints for submitting and managing support requests. |
| `/reports`          | Handles the reporting of incidents or issues related to jobs or users. |
| `/reviews`          | Manages reviews and ratings for jobs and workers.   |
| `/cornJobs`         | Triggers scheduled tasks, primarily for sending notifications. |

## Socket.io Events and Real-time Communication

Socket.io is integral to providing real-time updates and interactive experiences within the Sheftaya platform, especially for shift management and notifications. The system uses various events to communicate status changes instantly.

### Socket.io Initialization and Authentication
-   The Socket.io server is initialized in `config/socket.js`.
-   All incoming socket connections are authenticated using JWT tokens provided in the handshake. If authentication fails, the connection is rejected.

### User and Job Rooms
Upon successful connection, each socket joins specific rooms:
-   **`user:{userId}`**: A private room for each connected user, used for sending direct notifications.
-   **`role:{role}`**: A room for users based on their role (e.g., `employer`, `worker`), used for broadcasting role-specific updates.
-   **`job:{jobId}`**: Dynamic rooms that users (workers and employers) can join to receive real-time updates related to a specific job.

### Client-Side Socket Events (Emitted by Client)
-   **`join_job`**: Sent by a client (worker or employer) to join a specific job's room. Expects `jobId` as a parameter.
-   **`leave_job`**: Sent by a client to leave a specific job's room. Expects `jobId` as a parameter.
-   **`pingCheck`**: A debug event sent by the client to check connectivity. The server responds with `pongCheck`.
